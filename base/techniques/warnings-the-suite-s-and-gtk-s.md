A filter has to go in test/pytest.ini (the config file pytest finds, rootdir test/), not pyproject.toml, which pytest never reads here, and not warnings.filterwarnings() in test/__init__.py: pytest adds "always" for DeprecationWarning around each test, over the global filters, then applies the ini filters on top. - **An exception in a signal handler or idle callback fails the test** since 4d4e4900: MComixTest replaces `sys.excepthook` (which PyGObject calls to print such an exception before carrying on) for each test and fails it with the tracebacks.  Before that, 13 tests passed while their fakes raised AttributeError on every selection change.  A new fake window or library has to carry what the code it hosts reaches (`control_area.update_info`, `backend.get_book_by_id`, `imagehandler.get_current_page`).  The net does **not** see `mcomix.worker_thread.WorkerThread`: `_run` catches every exception and logs it with `log.error`, so a worker that raises in a test is visible only as a captured ERROR log line.
- **GTK's warnings are invisible without `-s`.** pytest captures each worker's stderr and prints it only for a failing test, so a warning that costs nothing visible hides for months. The sweep is `pytest test/ -q -n 8 -s > <log> 2>&1` and then `grep -oE "(Gtk|Gdk|GLib)-(WARNING|CRITICAL) \*\*: .{0,70}" <log> | sed -E 's/[0-9]{2}:[0-9]{2}:[0-9]{2}\.[0-9]+//' | sort | uniq -c | sort -rn`. At add07972 what is left is two "Finalizing ... but it still has children left" (a popover menu on a list view, a thumbnail grid) and one `gtk_root_get_focus: assertion 'GTK_IS_ROOT (self)' failed` per run; no MComix code calls either function.
