- **Pillow's ImageOps.invert() raises on RGBA** ("not supported for mode RGBA") and autocontrast() takes only L and RGB. Anything with an alpha channel that reaches `image_tools.enhance()` - a transparent page's thumbnail, an uncomposited placeholder - has its alpha set aside since 9319c063. `fit_in_rectangle()` composites onto the checkerboard, so what it returns is opaque; what skips it is not.
- **A `_BookArea` left unclosed hangs an xdist worker.** Its thumbnailer thread starts as soon as the view has items and parks on a condition; `area.close()` in `tearDown` is not optional. The symptom is the suite never printing a summary while the same file passes on its own.
- **`MComixTest` redirects `DATA_DIR` but does not create it.** Anything writing there must `os.makedirs` first.
- **`str.isdigit()` is not the test for what `int()` parses.** It is true of the superscripts (`²`), the circled numbers (`①`) and more, all of which `int()` refuses with ValueError. `str.isdecimal()` is true of exactly the Unicode decimal digits, which is both what `int()` accepts and what a regular expression's `\d` matches - so after splitting on `\d+|\D+`, `isdecimal()` is the test that agrees with the split. At 45eb29f9 this crashed the listing of any archive with such a character between two ordinary digits in a page's name. Two other places read the same way: version_tools._sort_key(), fixed with it, and pageselect's spin button, which cannot be reached because GTK leaves a numeric Gtk.SpinButton's text empty rather than accept the character.
- **win32/mcomix.nuspec has CRLF line endings, and win32/tools/chocolateyinstall.ps1 a UTF-8 BOM.**  A Python rewrite that reads in text mode and writes `\n` turns a one-line change into a 74-line diff; `git diff --stat` shows it.  Check with `git show HEAD:<file> | file -` before editing, and edit such files with the Edit tool or in binary.  The install script can be driven under pwsh from a copy in SCRATCH with a `checksum.sha256` beside it, `$env:ChocolateyPackageName`/`Version` set and `Install-ChocolateyPackage` defined as a no-op, then read `$packageArgs.url64bit`.
- **The win32/ build scripts import on Linux**: test/test_windows_build.py puts win32/ on sys.path and imports build_msi and build_pyinstaller, whose module level does nothing but define.  A version helper there must take the version as an argument: a default of `VERSION` is bound at definition, and `mock.patch.object(build_msi, 'VERSION', ...)` then changes nothing.
- **The library's delete and the window's delete are twins** (file_actions.py `_delete_answered`, library/book_area.py `_remove_answered`).  What one does to the records of a deleted file - library entry, recent files, bookmarks, the open book's unwritten changes - the other has to do; each gap found so far was the library lagging (59f23a30, 270daeab, 7d6bd1fe).
- **`__name__ = '...'` in a class body renames nothing** (393b16cf): it lands in the class's `__dict__`, and `cls.__name__` is answered by type's own descriptor. `grep -rn "^    __name__ = " mcomix/` found no other such line. To rename a class after the fact, assign `Cls.__name__` outside its body.
- **`callback += some_set.clear` raises** (at 1ea8755f): mcomix.callback keeps a weak reference to a bound method's `__self__`, and a built-in set cannot be weakly referenced. Bind a method of the listener that calls it instead.
- **The environment reaches the archivers** (at 7815e517): this machine sets `XZ_OPT="-T0 -9"`, which xz reads before its command line; -9 made 192 MiB blocks and one thread. A writer that runs a compressor names the preset and block size itself.
- **A test class that is not MComixTest reads whatever preferences the last test left** (at 88a82500): MComixTest resets them in setUp, not tearDown. A check of documented defaults reads `preferences._DEFAULTS`.
- **A preference default does not reach old files by itself** (at 8e4c6fa1): MComix 3 wrote every preference into the file, so a changed default needs a CONFIG_FORMAT_VERSION step dropping the old value. A migration test resets the preference before each read, since read_preferences_file() only updates what the file names.
