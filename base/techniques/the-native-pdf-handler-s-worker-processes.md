- **A probe that opens a PDF through `FitzArchive` and then calls `os._exit(0)` leaves the manager's process behind** - and, where the start method is forkserver (Python 3.14's default on Linux), the forkserver and the resource tracker too, all reparented to PID 1. `os._exit` skips the finalizer that shuts a `BaseManager` down, and the orphans keep the command's stdout pipe open, so the Bash tool waits for an end of file that never comes and the command looks hung.  Close the archive's manager (`archive._mgr.mgr.shutdown()`) before `os._exit`, or end with `sys.exit`, and list `ps -eo pid,ppid,args | grep forkserver` afterwards; kill leftovers by PID, never with `pkill -f`, whose pattern matches the tool's own shell.
- **What the worker sees depends on the start method.**  A forked worker inherits the parent's preferences; a forkserver or spawned one imports `mcomix.preferences` afresh and sees the defaults.  Anything the worker needs from the reader's settings has to be passed to it.
- **Measured on cf4dc21c, Python 3.14, PyMuPDF 1.28.2, GTK loaded first:** importing `pdf_multi` 275 ms (PyMuPDF itself about 220 ms of it); the first `page_count()` 260 ms under forkserver and 12 ms under fork. A `bench_pdf_open.py`-style probe: build the PDF in a separate process first, so the parent's own PyMuPDF import is not what is measured.
- **Forkserver on Python 3.12 and 3.13 listens on a socket file, whose path Linux caps at 108 bytes** (3.14 uses abstract sockets). Two things made it too long: multiprocessing works its temporary directory out once per process and it landed inside the first such test's directory, which `test/__init__.py` now pins to the session directory as it pins GLib's; and the session directory is inside the tree (`test/tmp/session.*`), so a tree under a deep path still fails every test that opens a PDF through the worker with "OSError: AF_UNIX path too long". Run the 3.12 floors environment on a short path (`EXPORT_DIR` in `STATE/config.sh`). A pinned process-wide cache of a temporary path is the thing to look for when a test passes alone and fails after a sibling.
- **Floors environments are cheap to build here.**  `uv python install 3.12`, then `uv venv --python 3.12 <dir>` and `uv pip install --python <dir>/bin/python 'PyGObject==3.46.0' 'pycairo==1.25.0' 'Pillow==10.1.0' 'PyMuPDF==<v>' chardet pytest pytest-xdist` builds against the system's GTK 4 and gobject-introspection headers in under a minute.  Swap one package's version per copy to bisect which floor a failure belongs to.
- (at 924052f7) **STATE/probes/pdf_workers.py counts the processes descended from the probe** while file_details() previews a PDF: 2 stay after any number of previews (the forkserver and the resource tracker, shared), ten previews at once peak at 12 and fall back to 2 within a second, so a closed FitzArchive does shut its manager down. Two traps it fell into first: a script run from SCRATCH imports the *installed* mcomix from site-packages unless it puts os.getcwd() on sys.path, and under forkserver every worker re-imports __main__, so the probe's body has to sit under `if __name__ == '__main__'` or it runs again in each worker. Count descendants, not children: the managers are the forkserver's children.
