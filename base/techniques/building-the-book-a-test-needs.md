- **An archive of any awkward shape is three lines in `setUp`**: `zipfile.ZipFile(os.path.join(self.tmp_dir, 'x.zip'), 'w')` and `writestr()` for each entry. A zip holding only `readme.txt` opens, is listed, and reaches `_archive_opened()` with no images, which is the state where `ImageHandler.get_current_page()` answers 0 while the file handler counts the file as loaded. `test/files/archives` has no such archive, and a crafted file is faster to read in a test than a binary fixture.
- **`get_current_page()` answers 0 for "no page"**, and code that stores or indexes by it has to say what 0 means. `git grep -n "get_current_page()" -- 'mcomix/*.py'` lists every reader; the one that stored 0 filed an unread archive in the library (ad74c94c).
- **The pages of `01-ZIP-Normal.zip` are 1 by 1 pixels**, so no zoom makes them scroll: the layout box stays the size of the viewport. For a page that scrolls, open `images/portrait-no-exif.png` (210 by 297; the directory gives 25 pages, and the page after it is shown beside it in double page mode), set `prefs['zoom mode']` to MANUAL, call `window.change_zoom_mode()`, and `manual_zoom_in()` eight times: 840 by 1188, with 818 pixels to scroll down under Xvfb (at 40c9c601). Landscape pages are shown alone in double page mode.
- **After a key press, wait for `_ScrollablePageTest._settle()`, never one pump** (test_key_press.py, at a05c505c): a page turn is drawn from the idle queue (`MainWindow._waiting_for_redraw` is set until it has run), a page not yet loaded leaves `window.images` hidden, and the canvas passes a new size to its adjustments only when next allocated, a frame later. Until all three are done the scroll bars describe the page before. A probe that pumped past this hid a deterministic bug (19338a00) as a 5% flake.
- **Set a scroll position through `PageCanvas.scroll_to()`**, not the adjustments: `Gtk.Adjustment.set_value()` clamps to the range it holds, which after `set_content_size()` is still the old content's until the next allocation.
- **Real key presses on the main window**: `test_key_press.py` `_KeyPressWindowTest._press(keyval)` goes through the X keymap and the real bindings; `KeyPressTest` adds a patch that records what the keybinding manager is handed instead of running it.
- **A layout with many combinations is checked by an invariant, not a table**: `test_spread_rotation.py` asserts that the step from the first page to the second equals the page transform applied to the unturned step, over 32 combinations of manga, rotation and flips. `Transform` matrices are row-major and act on (x, y) with y down: ROT90 = (0, -1, 1, 0) is clockwise on screen.
- **A RAR in volumes: `rar` 7.x is installed here** (at d518598f), so `rar a -m0 -v4k -idq out.rar files...` makes out.part1.rar... (RAR 5 only; rar 7 dropped -ma4). test/files/archives/Multivolume.part1-3.rar is four test images with 02.jpg and 03.jpg split. libunrar reads a split file's header once per volume (Flags 0x2 then 0x1 = RHDF_SPLITBEFORE); `unrar vt` stops at the first volume unless given `-v`, and then marks continuations with ratio "<--" or "<->"; `unrar p` and 7z read the whole set. A new file under test/files/archives needs its extension in test_archive_tools' _EXTENSION_TO_MIME_TYPES. Which volume is first is in the main header (at 450cf9e3, archive_tools.is_later_volume): RAR 5 archive flags 0x1 volume + 0x2 volume-number field on every volume but the first; RAR 4 HEAD_FLAGS 0x1 volume, 0x10 new numbering, 0x100 first volume. A RAR 4 header for a test is written by hand (sig, CRC16, 0x73, flags LE, size).
- **The external handlers cut one `p`/`x -so` stream by listed sizes** (at f1a9de5d): anything the listing parser leaves out of `_contents` never comes out of a solid pass. Empty members were dropped by a `size > 0` test meant for directories; a directory costs nothing in the stream and nobody asks for one, so recording it is harmless. A solid RAR with an empty member: `rar a -s` (SolidEmptyMember.rar). `_contents` grows on every listing and is never cleared (rar_external, sevenzip_external); harmless, since iter_extract stops once all it was asked for is out.
- **The main window's page transform with Exif** (at b5053c7e): landscape-exif-270-rotation.jpg is stored 210x297 with orientation 8; drawn with "auto rotate from exif" it is `Transform.from_rotation(270)` at 297x210 (test_view_actions).
- **A page that will not load** (at f5ae3ee9): a `.png` holding the PNG signature and junk, `b'\x89PNG\r\n\x1a\n not a picture'`. It is listed as an image, both providers fail on it, and `get_pixbufs()` answers `image_tools.missing_page()`. `test_skip_broken_pages._book('oxxo')` makes a directory book from a pattern: 'o' red.png, 'x' broken. Opening a directory book makes every page available at once, so the page order and the draws are deterministic; wait for `window._waiting_for_redraw` to stay False over two pumps.
- **The order an archive is unpacked in** (at 31fc662f): set `prefs['max extract threads'] = 1` and patch `archive_extractor.Extractor._extract_file` with a wrapper that records the name and calls the original; `wait_for` until every page is recorded (test_file_handler.ExtractionOrderTest). With one thread the order is exactly the extractor's queue, which `ImageHandler._ask_for_pages()` rebuilds on every page turn (nearest first, ahead before behind) and `_archive_opened()` fixes before `extract()` starts. A zip written with `writestr()` of red.png bytes under `%02d.png` names is 12 pages in four lines. Cost of building the order: `STATE/probes/extraction_order_bench.py` (stubbed file handler; 0.03 / 0.2 / 1.1 ms per turn at 200 / 2000 / 10000 pages).
- **A failing test prints every captured log line**: add `-p no:logging` and `grep -v DEBUG` to a pytest call whose output is grepped, or the FAILED lines drown in the debug log of every thread.
- **A key press without xdotool** (fc359783, test/test_key_press.py): `display.map_keyval(keyval)` gives the keycode, `display.translate_key( keycode, state, 0)` the keyval GTK would hand over with those modifiers, and `window.event_handler.key_press_event(stub, keyval, keycode, state)` runs the real handler; patch the keybinding manager's `execute` to record what it is asked for.  Caps Lock is `LOCK_MASK` in the state; it is how the Caps Lock bug was found.
- **Setting a JPEG's Exif orientation without compressing it again:** walk the segments from SOI to SOS (`FF xx` plus a big-endian length that counts itself; RSTn and TEM have none; `FF FF` is fill), drop an existing `APP1 "Exif\0\0"` after loading it into `Image.Exif()`, set the tag, and write `FF E1` + length + `exif.tobytes()` (which starts with "Exif\0\0" in Pillow 12) after a JFIF APP0, then everything from SOS on as it was.  Test it by comparing the bytes from `FF DA` on, before and after; a flat test image compressed again at the same quality can come out byte-identical, so use `Image.effect_noise` and quality 95. (native_pdf/child.py, jpeg_with_orientation.)
- **The window's menu actions and mouse buttons are reached through what the window exposes, not by events** (at 3b0ac2f0): an action by `window.actiongroup.get_action(name).activate()` then `pump()`, and what it drew read from `window.transforms[0]` (a Transform to compare with `Transform.from_rotation()` / `from_flips()`) or the size of `window.images[0].get_paintable()` (test_view_actions). Buttons go through `event_handler.mouse_press_event/mouse_release_event` with test_main_window's `_Click(button, state)`; set `window.was_out_of_focus = False` before the press, or under -n 8 another worker's window has the focus and the press is taken as the click that raises the window (the lens test failed 3 runs in 3 until it did). A popover a test opens needs `hold_open()` first.
- **A test that writes the book back must patch `file_actions.save_archive`**: MainWindowTest's book is the fixture archive under test/files itself.
- **A binary format is quicker to build in the test than to ship**: test/test_mobi.py writes a Palm database (78-byte header, 8-byte record index, records) with struct in twenty lines.
