- **xdotool drives real clicks under Xvfb**, and is the only way to learn what GTK actually does with a mouse button. Present the window, `wait_for` the layout, read the origin with `xdotool getactivewindow getwindowgeometry --shell`, then `xdotool mousemove X Y click N`, all in one process with the main loop pumped in between. It settled three guesses about GTK4 menus in one session, and confirmed that a button 2 press on a `Gtk.GridView` cell reaches a gesture added to the view.
- **A handler that works from code can still be unreachable by the mouse.**  Two bugs the user met were invisible to every test that emits signals: a question put to the main window while a modal window held the grab (OK drew but took no clicks, 2ade7ac0), and a drag whose cell held the keyboard focus (bdc4b7bd).  xdotool is installed here; in a probe on MComixTest, find the widget's point in its window with `widget.compute_point(window, Graphene.Point().init( w/2, h/2))`, add `window.get_surface_transform()` (the CSD shadow), and send `xdotool mousemove --window <window.get_surface().get_xid()> x y`, then `click 1`, or `mousedown 1`, a few `mousemove` steps and `mouseup 1`, pumping with short sleeps between. STATE/probes/test_zz_click_overwrite.py and the scroll probe in bdc4b7bd's iteration are the templates.  Keep this out of the suite: under `-n 8` every worker shares one Xvfb and one pointer.
- **A GTK list view scrolls when the focused entry leaves the model.** A click or drag focuses the entry's GtkListItemWidget; removing that item makes GTK focus another and scroll to it at the next layout, a frame later - restoring the adjustment synchronously does nothing. (corrected at 9169d0de) Restoring the value from an idle, with `scroll_to(pos, FOCUS, ScrollInfo disabled)`, only puts the view back a frame later - the user saw it blink, and `scroll_to()` scrolls even with the ScrollInfo disabled.  What keeps it still: `root.set_focus( None)` before the entry leaves the model, and after layout (an idle) `grab_focus()` on the list item widget now at the destination. Record every `value-changed` of the adjustment to see a blink; a final value alone does not.  STATE/probes/test_zz_drag_blink.py does it with a real xdotool drag. To give a cell that focus in a test: `cell.get_parent().grab_focus()`.
- **Which windows a modal window blocks (measured at 4f0aa3a4 with real xdotool clicks).**  While the archive editor is modal *and sensitive*, a non-modal dialog transient for the main window takes no clicks; one transient for the editor (the Save as chooser) does, and so does any modal dialog.  Make the editor non-modal, or insensitive (as `_pack_archive()` does while it saves), and the main window's dialog is clickable again - so the save-failure notice, parented to the main window, works only because the editor is insensitive then. A question asked from inside a modal window belongs to that window or is modal itself.
- **Nothing moves the pointer when the pages change under it (at 1f17e3bb).**  A real xdotool pointer resting over the page got no motion event after flip_page(); anything drawn from a motion handler (the lens) goes stale on a page turn or a scroll by key. STATE/probes/probe_lens_real_pointer.py is the probe.  In a test that drives a motion handler by hand, take the controller off the widget first: every xdist worker shares one Xvfb pointer, and a window mapped under it hears of that as motion.
- **Keyboard input into a real dialog**: `xdotool windowactivate --sync <xid>`, `windowfocus --sync`, then `type --delay 30 --window <xid> <text>` and `key --window <xid> Return`, pumping with short sleeps between; read `dialog.get_focus().get_text()` to see what arrived. STATE/probes/test_zz_password_typing.py opens encrypted archives in a MainWindow (optionally with the library open) and types the password. Out of the suite, as every xdotool probe.
- (at d8490484) **A second button pressed during a click is not a press to GTK**: with the middle button down, a right press made the page area's Gtk.GestureClick emit stopped and cancel for button 2, no pressed for 3, and both releases as unpaired-release. Log a gesture's signals by connecting pressed, released, stopped, cancel and unpaired-release before guessing (STATE/probes/lens_right_button.py). A middle-button drag of 120 px is not cancelled.
