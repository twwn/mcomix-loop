- **Reading the CI's results is the loop's** (the user's ruling, 2026-09-26), without the web page: `gh run list --repo twwn/mcomix --json databaseId,workflowName,conclusion,headSha` for the runs; `gh run view <id>` for the jobs and `--log-failed` for what failed; `gh run view <run> --repo twwn/mcomix --log > file` for a whole log (the jobs/<id>/logs endpoint refuses output with escape sequences); `gh api repos/twwn/mcomix/actions/runs/<id>/jobs` for job times, `gh api repos/twwn/mcomix/actions/jobs/<job>` for step times, `gh api repos/twwn/mcomix/check-runs/<job>/annotations` for notices (the ubuntu-latest migration notice came from there); `gh release view <tag>` for what a release published. Never `gh run watch` (it blocks past the tool's timeout); wake again later instead. A run is started by the user's push, which the loop cannot make.
- **Linting the workflows** (at 753b11dd): `uvx zizmor --offline --persona=auditor .` (zizmor 1.30.1; covers dependabot.yml too) and `uvx --from actionlint-py actionlint .github/workflows/*.yml`. actionlint 1.7.12 does not know the ubuntu-26.04 label: pass `-ignore 'label "ubuntu-26.04" is unknown'`. No shellcheck here, so actionlint does not check the `run:` scripts. What stays on zizmor's list on purpose: unpinned-uses for actions/* and github/* (third-party actions are pinned by commit, first-party by major version), msys2 {0} as a default shell (misfeature), self-repository, concurrency on the dispatch-only workflows.

Neither says whether glycin's sandboxed loaders run on a runner: only a run does.

- **What the CI met at 393b16cf, and what cannot be seen here** (0c2b897f..8a0f4352): the floors job builds boxed types with PyGObject 3.46, which drops constructor arguments - `Gdk.RGBA(red=...)` is transparent black there; build colours with `image_tools.rgba()` in tests as the code does. libadwaita on the CI is 1.5.0 (Ubuntu 24.04), which has no stylesheet of the kind theme._adwaita_colours() reads (light and dark state nothing there). - **The suite runs the garbage collector itself** (8a0f4352): test/__init__.py calls gc.disable() and MComixTest collects on the main thread every 25 tests, so no worker thread ever starts a collection over GTK objects. A gc.collect() after every test took the floors run from 34 s to 87 s. A probe or test that needs cyclic garbage gone at a certain point calls gc.collect() itself, as test_dialog_freed does.
- **Where each libadwaita keeps the colours MComix reads** (d67f20fb, from the gresources.xml of each tag): up to 1.7.0 /org/gnome/Adwaita/styles/defaults-light.css and defaults-dark.css (top-level @define-color, one file per variant); 1.8.0 default.css (light at top level, dark under `@media (prefers-color-scheme: dark)`, one line per block from sassc's compact style) beside main.css and high-contrast.css; 1.9.0 gtk.css, laid out as 1.8's default.css. Read the sources with `curl -sfL https://gitlab.gnome.org/GNOME/libadwaita/-/raw/<tag>/src/stylesheet/<file>`; `Gio.resources_enumerate_children('/org/gnome/Adwaita/styles', 0)` after `Adw.init()` lists what the installed one carries. A test that names a version boundary checks it against two tags, not one: the "since 1.6" of 27570ede was a guess and was wrong.
