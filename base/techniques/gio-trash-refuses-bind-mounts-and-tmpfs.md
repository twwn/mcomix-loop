- **When GLib trashes.** A file on the home directory's device goes to `$XDG_DATA_HOME/Trash`. Any other file goes to its mount's `.Trash-<uid>`, unless GLib counts that mount as internal to the system: then `G_IO_ERROR_NOT_SUPPORTED`, "Trashing on system internal mounts is not supported". GLib 2.90 counts every mount whose root is not "/" as internal (a bind mount, a btrfs subvolume mounted by path), every tmpfs, and paths such as /tmp. On this machine `/home/<user>/Downloads` is `/dev/nvme1n1p1[/Downloads]` (`findmnt -lno TARGET,FSTYPE,SOURCE`), so nothing in it can be trashed; the user's report of a ZIP that "could not be deleted" came from there (1a93048c).
- **Read-only check, no trash touched:** `tools.trash_refuses(path)` (676ab7c0) is GLib's rule in Python. `GioUnix.mount_entry_at(path)` returns `(entry, time)`, and only for the exact mount path (None for a home folder or a checkout that is not itself a mount point; walk up while `st_dev` stays the same first); `entry.is_system_internal()` (or `GioUnix.mount_is_system_internal(entry)`) and `entry.get_root_path()` say what GLib will decide (`gi.require_version('GioUnix', '2.0')`). (corrected at 676ab7c0: there is no `GioUnix.mount_entry_is_system_internal` in GLib 2.90's typelib.) A mount GLib does not know (entry None) is refused too, and so is "/" when the home folder is on another device. Compare `stat -c %d` of the file's folder and `$HOME` first: the same device always goes to the home trash. A file in the scratchpad (tmpfs) is a safe place to see the error itself; never trash a file under the user's home to find out, it lands in their real trash.
- **Tests never reach a real trash:** `test/__init__.py` replaces `tools.trash_refuses` with `lambda path: False` (the real one is `test.real_trash_refuses`, for test_tools' TestTrashRefuses, which mocks GLib.get_home_dir and GioUnix.mount_entry_at) and `tools.move_to_trash` with a move into the running test's `trash_dir`; a test that wants the refusal patches `tools.move_to_trash` (or `book_area.tools.move_to_trash`) with a function raising `GLib.Error('Trashing on system internal mounts is not supported')`. What happens next is `FileActions.offer_to_delete_permanently()` (93c8cba6), whose buttons answer `Response.CANCEL` (default) and `Response.OK`.
- **A MessageDialog built without `buttons=` has none** (the default is `Gtk.ButtonsType.NONE`), and one shown that way cannot be closed. An ast sweep of `MessageDialog(...)` assignments with no `buttons` keyword whose function never calls `<var>.add_button(` found only `_trash`'s at 4052148a (the bookmark one uses `add_buttons`, a false hit).
- **Where the refusal is foreseen** (676ab7c0), Delete asks `_ask_to_delete_permanently()` at once and the library asks with `add_delete_permanently_buttons()` (Response.CANCEL/OK, mapped to NO/YES for `_remove_answered(..., permanently=True)`); `offer_to_delete_permanently()` is left for a refusal not foreseen. A test wanting the foreseen case patches `tools.trash_refuses` (`book_area.tools` is the same module) with `return_value=True`.
- **Dialog button labels in a module listed in test_messages' MENU_MODULES count as that module's menu**: `MnemonicTest.test_no_menu_has_two_items_on_one_key` read '_Cancel'/'_Delete Permanently' written in book_area.py as items of its covers menu and failed in 10 languages. Reuse a helper from another module (file_actions' button helper) or YES_NO from message_dialog.py instead of writing a label there.
- **GLib 2.84 renamed the calls** (g_unix_mount_at to g_unix_mount_entry_at, and so on); 2.80 to 2.83, Ubuntu 24.04's (the floors job), have only `GioUnix.mount_at()` and `GioUnix.mount_is_system_internal(entry)`, and 2.90 warns "GioUnix.mount_at is deprecated" for those. `tools._mount_has_no_trash()` picks by `hasattr(gio_unix, 'mount_entry_at')` (1368363a). Patching `GioUnix.mount_entry_at` in a test fails where the attribute does not exist; patch `tools._gio_unix` to return a SimpleNamespace of either shape instead.
