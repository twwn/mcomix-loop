- **Comments narrating the GTK3 port**: `grep -nE "^\s*#.*(used to |There (was|were) |was only ever|GTK3|Gtk\.Table|Gtk\.EventBox|Gtk\.Layout|went with|is gone|no longer )" mcomix/**/*.py` over every tracked file. It over-matches ("no longer" is often present tense, and a docstring explaining why a class exists is fine), so read each hit with a few lines of context. Check any claim a comment makes about what GTK does before rewriting it into the present tense: one said a scrolled window recomputes the adjustments, and the widget is a custom `PageCanvas` that does it in `_configure()`.
- **Private names reached across objects**: `git grep -n "\.[a-z_]*\._[a-z]" -- mcomix` and, per name, `git grep -nw <name> -- mcomix test` to size it. A leading-underscore attribute or method used from another module is either an interface that should lose the underscore or a sign the caller wants a coarser method. Rename with `sed -E 's/\b_name\b/name/g'` over the named files and confirm with `git grep -nw _name` that nothing is left, including strings in tests that patch the method by name.
- **Port narration the first sweep misses**: comments that name GTK4 to contrast it with what GTK3 had. `grep -nE "^\s*#.*(GTK ?4|in GTK|is gone| went with)"` over tracked files, then read each: "GTK4 has no X, so Y" states a constraint the code still works under and stays; "X is gone in GTK4", "X is Y in GTK4" and "the old handler sat there" narrate the port and go. Past tense in a comment next to a fix ("used to leave", "the closure held one and the timer went on") is the same kind of narration and is rewritten into what the code must do and why.
- **Every `except Exception` in mcomix/, read one by one** (38 at ba358e90; `grep -rn -B6 -A4 "except Exception" mcomix/` into a file under SCRATCH). All but one are deliberate and say so in a comment: decoder fallbacks in image_tools, worker threads that log because nothing joins them, a corrupt file read at start-up. What the sweep is looking for is the handler over an operation the *user* asked for and is watching: file_actions._save_page_to() logged a failed "Save page as" and nothing more, so the chooser closed and no page appeared. Still open, same shape: library/book_area.py's _remove_answered() logs a book it could not delete from disk while the entry is gone from the library, so the reader is told the file was deleted when it is still there.
- **Activating a stateful boolean `Gio.SimpleAction` that has only a `change-state` handler asks for the opposite of its state**: a bare Gio probe (`new_stateful('x', None, GLib.Variant('b', False))`, connect `change-state`, `activate(None)`) delivers True. So a toggle whose state has fallen out of step with the preference it stands for makes the next keyboard activation set the preference to what it already is. No MComix import is needed, so nothing can reach the real home.
- **Text read in the machine's encoding**: an `ast` walk for `open()` calls whose mode has no `b` and whose keywords have no `encoding` (over `mcomix/**/*.py`). At 11c6d882 there were four. Three read JSON that `json.dump` wrote with its default `ensure_ascii`, so the files on disk are pure ASCII and no encoding can change what comes back - hygiene, not a bug, and not worth a commit that proves nothing. The fourth read a comment file out of an archive, which is whatever its author wrote: it raised UnicodeDecodeError, was caught, and the Comments dialog said "Could not read" instead. `i18n.to_unicode()` is what this code base decodes unknown bytes with (chardet where installed, then the locale, the file system encoding, UTF-8, Latin-1, and UTF-8 with replacements), and a test proves the fix by writing a Latin-1 comment into a zip with `ZipFile.writestr()`, which takes bytes. The same sweep over `subprocess` found every external archiver already passing `encoding='utf-8'`, and `bytes.decode()` with no argument is UTF-8 rather than the locale, so it is not a finding.
- **Preferences nothing can change** (at 1b4312ef): for each key of `preferences._DEFAULTS`, look for a write (`prefs['k'] =`, `|=`, `+=`, a mutating method) and for the key named as a string anywhere outside `prefs[...]` (the dialog's controls take names). A key with neither, or whose only write sets it back to its default, is dead: "thumbnail bg uses main colour" had lost its radio button in 2011. The sweep's regex must include `|=`, or "statusbar fields" (set bit by bit in status.py) shows up falsely.
- **Parameters no caller passes**: `check_restrictions` of OpenWithCommand.parse() (8075ff9d) - coverage showed its branch unreached, and `git log -S'check_restrictions=False'` found no caller ever.
- **ruff's bug rules** (at 4165c4b2): `ruff check --isolated --select B,PLE,PLW,PIE,S110,S112,FURB,RUF012 --target-version py312 mcomix` (133 hits). PLW1510 (subprocess.run without check) led to four calls without process.CREATIONFLAGS, a console window per call on Windows (4165c4b2; NoConsoleWindowTest now guards it). Read and left: B020 and PLW2901 (loop variables rebound on purpose), B011 (assert False for programming errors), S110 (fallbacks to another decoder), PLW1641 (Box and Matrix are compared, never hashed), B905 (zip without strict), RUF012, FURB167 (re.I), PIE790/808, B007, B010.
- **Preference names mypy cannot check** (at e0db14c1): `prefs['...']` is checked against the Preferences TypedDict, but a name compared as a string (`preference == '...'`, `preference in (...)`) is not; one such name had outlived its preference since 03df90ef. An AST sweep of Compare nodes whose left side is `preference`/`prefkey`/`name`/`key`, against `preferences._DEFAULTS`, found no other.
- **Count what a refactor must reach before proposing it.** An `ast` walk for `_()` calls outside function bodies sized the interface-language hot-reload in one command: 257 msgids translated at import time.
- **Extraction threads, per format: `STATE/probes/extract_threads_bench.py`** (at 9ac7f6f0). `timeout -k 5 600 python3 <probe> <workdir> [pages]` from the checkout: builds 120 noise JPEGs (110 MB) once, packs them as zip, rar, solid rar, 7z, solid 7z, tar and pdf, and times the Extractor unpacking each with 1, 2, 4, 8 threads (best of three). No window. `ONLY=zip,pdf` limits the formats; `FORCE=zip,tar` makes those handlers claim concurrency, to measure what it would bring. The body is under `if __name__ == '__main__'`: the native PDF handler starts worker processes that re-import the main module, and without the guard each re-ran the benchmark. Numbers at 8e4c6fa1: 7z non-solid 1.18 s at one thread, 0.13 s at eight; zip 0.40/0.08; PDF 2.14/0.94; libunrar 0.06 and tar 0.04 at any count; solid 7z 2.0 s, bounded by 7z decoding one LZMA2 chunk per thread.
- **Archive writers: `STATE/probes/pack_threads_bench.py`** (at 52a0ad6a). `timeout -k 5 600 python3 <probe> <pages dir> <workdir>`: writes the directory with each make_writer() format and prints wall time, CPU time (own plus children) and their ratio, which is how many cores it kept busy. Noise JPEGs are the worst case for compressors; a directory of PNG pages made from the Pepper&Carrot book is the compressible one. At 7815e517: rar x10, 7z x12 (after c=16m), tar.xz x11.6 through xz, zip, gz and bz2 x1.0.
- **Write-then-move sequences** (at a042d69d): archive_packer removed the old archive before renaming the new one over it and set the mode after the move; both left the book lost or overwritten when the step after failed (de3379f6, a042d69d). The shape to look for: anything done to the destination after the step that can no longer be undone. A test that makes a move fail should patch os.rename and os.replace both, keyed on the target path, so that it does not break when the code switches from one to the other (test_edit_dialog's did).
