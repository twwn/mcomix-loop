- **Make the rare case common before touching anything.** A probe file that subclasses the test class and defines 24 copies of it (`globals()['Probe%d' % i] = type('Probe%d' % i, (_Probe,), {})`, with the original test methods set to None on the base) run under `-n 8 --cov=mcomix --cov-report=` turns one failure in nine suites into several per run; coverage slows everything, which is what widens the window. Count failures over six runs on the old and the new code
  - 8 of 144 against 0 of 288 was the evidence for 84dea538. Have the probe print what moved (the adjustment's value-changed and notify::upper, with values) so the failure says which way it went.
- **An idle callback is not "after the next layout".** GTK4 lays out and paints when the frame clock ticks, which is time-driven; an idle queued now can run before that frame. Code that must act on the widgets where they will be drawn connects once to the frame clock's `after-paint` (and `request_phase(LAYOUT)`), keeping the idle only for a widget with no clock (`thumbnail_list._focus_after_layout`).
- **Read the flake's own expectation too** (at f39a822a): a smart-scroll test failed expecting (22, 14, 14) and getting the right (22, 214, 820); the test had read its expected end from the scroll bars before they knew the page's size. Log the expected value beside what moved. Under xdist a worker's stdout is not shown, even with -s: the probe writes its log to a file under SCRATCH (test_zz_shiftspace.py style: 24 copies, each appending on failure). A module that imports the test class it copies also collects the original's tests.
- **A flake in one CI Python only: run the probe in the floors venv** (at 1c42d6e4). `STATE/scratch/floors/bin/python` is CPython 3.12 with the floor dependencies; the host is 3.14. The "gates (3.12)" flake was MComixTest._restore()'s rmtree racing FileHandler.thread_delete() over tmp/mcomix.*: 3.12's rmtree hands an entry that vanished to onexc, 3.13+ ignores it, so no host run could fail. STATE/probes/test_zz_delete_race.py forces the overlap (the deletion thread fills the book's directory with 20000 files, waits for _restore() to put tempfile.tempdir back, then deletes): 17 of 17 failed on 3.12 before, 0 after. Anything a closed book leaves to a thread must be finished before the test directory goes.
- (at 7eebfcc4) **A popover a test opens is closed by the other xdist workers.** They share one X server, and an autohide popover closes when its window loses the focus, which any other worker's presented window takes. test.hold_open(popover) turns autohide off; use it in every test that asserts a menu opened. Found with the 24-copies probe above (10 to 14 of 25 failing per run, 0 of 315 after); waiting for the window to be mapped did not help. The probe run with `--cov` writes .coverage into the checkout unless COVERAGE_FILE points elsewhere: set it, or remove the file before committing.
- (at f04edfc0) test_zz_preview_race.py: the same forced overlap for the file chooser preview thread on the floors venv (STATE/scratch/floorsenv, CPython 3.12.14; the path scratch/floors above no longer exists): 17 of 17 failed with PROBE_BEFORE=1, 0 of 17 after. A probe that patches a module for a thread must hold the patch until the thread is inside it: a cleanup added after patcher.stop runs before it. The first two versions passed because the slow rmtree was never reached, and a pass that fast (3 s for 17 runs of 20000 files) was the sign.
- (at 78870f1d) **A worker hands its result over before it takes the order off its list.** With `unique_orders`, worker_thread._run() removes the order after _process_order() returns, so a test that sees the thumbnail arrive and at once orders the same item again has that order dropped as a duplicate: the floors job waited 10 s for a read that never began. `STATE/probes/slow_order_end.py` (`PYTHONPATH=STATE/probes pytest -p slow_order_end`) holds a thumbnail worker 0.3 s after it hands over, which makes the rare case certain. A test that orders again waits for `covers._thread._orders_set` to be empty first.
